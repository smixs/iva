# Google Calendar: перенос события

1. Найди событие через `gws calendar events list`, пройди все страницы по `nextPageToken`, затем
   получи точный объект через `gws calendar events get`.
2. Покажи название, календарь, начало, окончание, длительность и признак повторения.
3. Для повторяющегося события уточни область переноса и выбери API-target:
   - вся серия → получи родительское событие по `recurringEventId` экземпляра и используй ID
     родителя как `eventId`;
   - один экземпляр → найди его через `gws calendar events instances`, проверь `recurringEventId`
     и `originalStartTime`, затем используй возвращённый ID экземпляра как `eventId`.
4. Уточни новое начало. При отсутствии новой длительности сохрани исходную длительность.
5. Определи итоговые напоминания: сохрани текущий массив `overrides`, а при `useDefault:true`
   используй `Calendar defaults` из CORE. При отсутствии сохранённого профиля уточни напоминания.
6. Проверь все страницы событий целевого интервала и покажи совпадения либо пересечения.
7. При наличии участников уточни режим `sendUpdates`: `all`, `externalOnly` или `none`. Покажи
   выбранный режим в dry-run и финальном подтверждении и передай его через `--params`.
8. Для изменения времени прочитай `gws schema calendar.events.patch`, собери `start`, `end` и полный
   объект `{"useDefault":false,"overrides":[...]}`, затем выполни `gws calendar events patch`
   с `--dry-run`.
9. Для переноса между календарями прочитай `gws schema calendar.events.move` и уточни целевой
   календарь. Вызови `gws calendar events move` и передай через `--params` исходный `calendarId`,
   выбранный `eventId`, `destination` и, при наличии участников, `sendUpdates`; тело запроса
   относится к отдельному patch.
10. При `useDefault:true` подготовь сначала отдельный patch с итоговыми напоминаниями, затем move.
    При наличии участников для подготовительного patch покажи `sendUpdates:none`, а для move —
    выбранный пользователем режим. Выполни оба запроса с `--dry-run`.
11. Покажи итоговые параметры и последовательность запросов, затем запроси явное подтверждение.
12. После подтверждения снова получи API-target и сравни `etag`. При совпадении сразу выполни
    подтверждённую последовательность. При изменении покажи актуальную версию и запроси новое
    подтверждение.
13. Выполняй запросы последовательно и проверяй ответ каждого. Первая ошибка завершает
    последовательность: снова получи событие, перечисли выполненные и ожидающие шаги и предложи
    компенсацию выполненного patch либо новое dry-run и подтверждение для продолжения.
14. После успеха сообщи итог из ответа API.

Для события со временем используй RFC3339 и IANA timezone. Для all-day используй `start.date` и
`end.date`; `end.date` указывает следующий день после последнего дня события.

Для нового времени используй часовой пояс из запроса, затем часовой пояс события, затем
`Calendar defaults`.

Передавай поля, относящиеся к переносу. Исходные название, описание, место и участники сохраняются.
Напоминания сохраняются из текущего `overrides` либо становятся явными значениями профиля
`Calendar defaults` при исходном `useDefault:true`. Перенос между календарями применяется к
событиям типа `default`.
