# Todoist

Задачи и напоминания в [Todoist](https://todoist.com). У тебя есть CLI `scripts/todoist.mjs` —
вызывай через `bash`. Вывод всегда одна строка JSON: парси её, не пересказывай сырьё.

## Проверка авторизации (ВСЕГДА первым делом)

Коды выхода как у `gws`: `0` ок · `1` ошибка API · **`2` не авторизован** · `3` неверные аргументы.

Если любая команда вернула код **2** — токен ещё не подключён. Не повторяй запрос в цикле: перейди
к разделу «Подключение» ниже и проведи пользователя по шагам.

```bash
node scripts/todoist.mjs auth        # {"ok":true,"authorized":true,...} либо код 2
```

## Если подключён и Google (пересечение)

Задачи, тудушки, списки дел и напоминания «сделать X» умеет **и** Google (Google Tasks +
напоминания в Календаре), и Todoist — это пересекающиеся хранилища, а не разные по смыслу. Куда
писать — **выбор пользователя, а не функции**.

- Подключён только один сервис → работай с ним.
- Пользователь явно назвал куда («в Todoist», «в гугл-задачи») → туда. Простое упоминание слова в
  тексте — не указание на аккаунт.
- Оба подключены и куда писать неоднозначно → **спроси через `ask_question`** (кнопки Todoist /
  Google) и действуй по ответу. Не выбирай молча.

## Чтение (сразу выполняется)

```bash
node scripts/todoist.mjs projects                      # список проектов {id,name}
node scripts/todoist.mjs tasks                          # открытые задачи
node scripts/todoist.mjs tasks --project 2203306141     # задачи одного проекта
node scripts/todoist.mjs tasks --filter "today"         # фильтр Todoist: today, overdue, "#Работа" …
node scripts/todoist.mjs get --id 6X4gp                 # одна задача
```

## Мутации (создать / закрыть / переоткрыть / удалить)

CLI выполняет мутацию **сразу**. Ветвление и подтверждение — на тебе, через встроенный инструмент
`ask_question` (он рисует кнопки прямо в Telegram). Правило:

- **Создание** по явной и однозначной просьбе («добавь задачу купить хлеб на завтра») → выполняй
  сразу, потом покажи результат. Отдельное подтверждение не нужно.
- **Закрытие / удаление** и любой **неоднозначный** случай (несколько подходящих задач, неясный
  проект/срок) → сначала `ask_question` с конкретными вариантами кнопками, затем действуй по выбору.
  Удаление необратимо — по нему спрашивай всегда.

```bash
node scripts/todoist.mjs add --content "Позвонить в банк" --due "tomorrow 10am"
node scripts/todoist.mjs add --content "Отчёт" --project 2203306141 --priority 3
node scripts/todoist.mjs close  --id 6X4gp
node scripts/todoist.mjs reopen --id 6X4gp
node scripts/todoist.mjs delete --id 6X4gp
```

`--due` — задаёт **срок** задачи естественным текстом, Todoist сам разбирает: `"tomorrow 10am"`,
`"every monday"`, `"18 aug"`. Это именно срок, а не отдельное напоминание: если у задачи есть время,
Todoist пришлёт своё уведомление по **настройкам уведомлений пользователя** — гарантировать это ты не
можешь. Отдельные пользовательские напоминания (reminders) — самостоятельная сущность Todoist (часто
платная), этот CLI их не создаёт; для «напомни мне» ставь срок со временем через `--due`.
`--priority` 1..4 (4 — срочно).

Пример ветвления перед закрытием (когда задач с похожим текстом несколько): вызови `ask_question`
с вариантами — по одной кнопке на задачу («Купить хлеб — сегодня», «Купить хлеб — просрочено») плюс
«Отмена», затем `close --id <выбранный>`.

## Подключение (когда `auth` вернул код 2)

Токен вводится **только через меню** — там приём идёт вне модели: мост перехватывает сообщение,
сразу его удаляет и пишет файл `0600`, так что при вводе токен не проходит через твой контекст и не
остаётся в переписке. **Не принимай токен в чате сам** и не проси прислать его тебе — тогда секрет
реально попадёт в твой контекст (в отличие от ввода через меню). Проведи пользователя по шагам:

1. Открой в боте `/menu` → **✅ Todoist** → **Прислать токен**.
2. В Todoist: **Settings → Integrations → Developer** → скопируй **API token**.
3. Пришли его в чат по подсказке меню — оно перехватит и сохранит его само.

После этого проверь `node scripts/todoist.mjs auth` и подтверди, что подключилось.

(`set-token`/`logout` у CLI — для локального администратора на сервере, не для приёма токена в чате.)
