# Google Calendar: создание события

## Профиль календаря

Перед первой записью проверь блок CORE на строку `Calendar defaults:`. При отсутствии строки сообщи,
что ответы станут сохранённым профилем, и одним сообщением уточни:

- основной часовой пояс IANA;
- календарь (`primary` или ID);
- напоминания: `popup`, `email` или оба и интервалы в минутах;
- стандартную длительность;
- занятость `opaque` или `transparent`;
- видимость `default`, `private` или `public`.

Сохрани текущие строки `CORE.md` и через `write_file` добавь либо замени одну компактную строку:

```text
Calendar defaults: timezone=Europe/Moscow; calendar=primary; duration=60m; reminders=popup:30,email:1440; transparency=opaque; visibility=default
```

Явные параметры текущего запроса имеют приоритет. При отсутствии отдельных значений уточни их перед
созданием. Запрос пользователя на изменение defaults обновляет эту строку.

## Один объект события

- Каждой реальной встрече, поездке, занятию или другому временному интервалу соответствует один
  объект Google Calendar.
- Все моменты оповещения относятся к `reminders.overrides` этого объекта. Фразы «напомни за день,
  за час и за 10 минут» описывают три напоминания одного события.
- Создавай поля, явно заданные пользователем или сохранённые в профиле.
- Для офлайн-встречи записывай физический адрес в `location`. Для онлайн-встречи записывай
  переданный URL в `location`. Google Meet создавай через `conferenceData` по явной просьбе.
- Для события на весь день используй `start.date` и `end.date`; `end.date` указывает следующий день
  после последнего дня события.
- Для события со временем используй RFC3339 в `start.dateTime` и `end.dateTime`, а часовой пояс IANA
  передавай в `start.timeZone` и `end.timeZone`.
- Для повторяющегося события уточни правило, дату завершения и исключения. Передавай часовой пояс
  IANA вместе с началом и окончанием серии.
- Участников, описание, место, конференцию, повторение, цвет и остальные дополнительные поля
  включай из запроса пользователя.
- При наличии участников уточни режим отправки приглашений: `all`, `externalOnly` или `none`.
  Передай выбранный `sendUpdates` в `--params` рядом с `calendarId`; в `--json` передавай ресурс
  события.

## Напоминания

- Всегда игнорируй `defaultReminders` из Google Calendar API.
- Всегда передавай `reminders.useDefault: false` и полный массив `reminders.overrides`.
- Сначала используй напоминания из текущего запроса, затем сохранённый профиль `Calendar defaults`
  из CORE. При отсутствии напоминаний в обоих источниках уточни каналы и интервалы у пользователя.
- Явный выбор «напоминания отключены» кодируй пустым массивом `overrides`.
- Объединяй напоминания события в одном массиве и убирай одинаковые пары `method + minutes`.
- Используй до пяти напоминаний. Методы: `popup`, `email`. Интервал: целое число от 0 до 40320 минут.
- При запросе большего количества либо интервала за пределами диапазона покажи ограничение API и
  попроси пользователя выбрать допустимые значения.

## Проверка и запись

1. Прочитай схему: `gws schema calendar.events.insert`.
2. Запроси события целевого календаря на выбранном интервале через `gws calendar events list`
   с `timeMin`, `timeMax` и `singleEvents:true`. При наличии `nextPageToken` повторяй запрос с этим
   `pageToken` до последней страницы и объединяй массивы `items`.
3. По полному набору событий найди совпадения времени и смысла, покажи найденное событие и предложи
   обновление либо создание.
4. При пересечении покажи конфликт и запроси решение пользователя.
5. Собери `--params` с `calendarId` и, при наличии участников, выбранным `sendUpdates`; подготовь
   один JSON-ресурс события и вызови `gws calendar events insert` с `--dry-run`.
6. Проверь метод `POST`, календарь, один объект, начало, окончание, `reminders.useDefault: false`
   и полный массив `reminders.overrides`.
7. Покажи итоговое название, календарь, начало, окончание, место, напоминания, участников и режим
   отправки приглашений, затем запроси явное подтверждение.
8. После подтверждения выполни тот же запрос в рабочем режиме и сообщи результат из ответа API.

Явная просьба «создай», «добавь» или «поставь в календарь» с полностью определёнными параметрами
запускает подготовку, dry-run, показ итоговых параметров и финальное подтверждение.

## Чувствительные данные

Проверяй текст на пароли, токены, коды доступа, платёжные реквизиты, паспортные и медицинские
данные, приватные адреса и другие чувствительные сведения. Покажи категории и маскированные
идентификаторы обнаруженных сведений, а точные значения сохрани в подготовленном запросе. Напомни о
возможном доступе участников и читателей календаря и включи сохранение в финальное подтверждение.
После подтверждения выполни insert с точными значениями в поле, указанном пользователем.

## Пример

Helper `calendar +insert` принимает основные поля события. Полный объект напоминаний передавай через
Discovery-команду:

```bash
gws calendar events insert \
  --params '{"calendarId":"primary","sendUpdates":"all"}' \
  --json '{
    "summary":"Встреча с командой",
    "start":{"dateTime":"2026-08-03T14:00:00+03:00","timeZone":"Europe/Moscow"},
    "end":{"dateTime":"2026-08-03T15:00:00+03:00","timeZone":"Europe/Moscow"},
    "location":"Москва, ул. Пример, 10",
    "attendees":[{"email":"member@example.com"}],
    "transparency":"opaque",
    "visibility":"default",
    "reminders":{
      "useDefault":false,
      "overrides":[
        {"method":"popup","minutes":30},
        {"method":"email","minutes":1440}
      ]
    }
  }' \
  --dry-run
```
